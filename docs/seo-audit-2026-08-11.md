## Production findings

On 2026-08-11 all four origin variants returned HTTP 200 instead of a server-side redirect:

- `http://batchbarcode.com/`
- `https://batchbarcode.com/`
- `http://www.batchbarcode.com/`
- `https://www.batchbarcode.com/`

The static pages intentionally do not use a JavaScript canonical redirect. Configure two Cloudflare Redirect Rules after deployment:

1. HTTP to HTTPS while preserving host, path and query.
2. `batchbarcode.com/*` to `https://www.batchbarcode.com/${path}` while preserving query.

Cloudflare Pages `_redirects` cannot perform hostname-level redirects, so this must be configured as a Cloudflare Redirect Rule, Bulk Redirect, or Worker.

## Decisions

- Long-term PDF417 URL: `/`.
- Single batch workflow URL: `/barcode-generator/`.
- Next workflow page: improve `/barcode-generator/` for CSV / Excel to printable barcode-label PDF; do not add `/bulk-barcode-generator/` or `/batch-barcode-generator/`.
- Expansion gate: wait for indexing, non-brand impressions, and generation-to-export behavior before creating another landing page.
- Weekly dashboard: indexed canonical pages; non-brand impressions/clicks; generation-to-export-or-print completion rate.
